# Local application verification

- `bkt_web/profile_session.py` quản lý Chrome profile theo kênh và các setting profile; không kill Chrome mở tay và không bấm Đăng lại task đã có `clicked_post_at`.

- The FastAPI app runs with `python3 -m bkt_web.server` at `http://localhost:8080`. The existing server process does not automatically reload backend changes; ask before restarting a server you did not start.
- Remake tests: `python3 -m unittest discover -s tests -p test_remake_pipeline.py`. Tests mock story-analysis network calls; the native-renderer smoke test requires installed Playwright Chromium.
- JavaScript syntax: `node --check bkt_web/static/app.js`.
- Remake templates in `bkt_web/remake_templates/` belong to the existing Canvas engine, not the separate HyperFrames projects in `compare_studio/`.
- Reviewed remake scripts are keyed by the source file SHA-256 in `bkt_web/storage/remake_verified_scripts.json`. Preserve explicit source scene times and speaker IDs; never assign speakers cyclically or divide scene durations evenly.
- Native Canvas templates expose deterministic `window.renderFrame(seconds)` for frame-by-frame export. Do not start autonomous animation loops when `?render=1` is present.
- CapCut CLI takes `--out`, not `--output`. TTS cache keys include text, engine, voice and role. A failed voice or render must not fall back to source footage/audio while claiming a completed remake.
- Shared vector library: `bkt_web/static/remake_vector_catalog.json` is the catalog/schema source; `remake_vector_engine.js` renders it. Select `native-vector-v1` on every scene; use `asset` IDs, absolute-time `poses`, named-anchor `attach_to`, and typed `actions`. The composer embeds the engine and catalog for offline frame rendering. Expanded to 110 rigs (quadrupeds, birds, insects/frog, 17 fruits, 10 flowers, tools, props) and 32 actions (`graze`, `pollinate`, `dig`, `hop`, `fly`), engine `1.11.0` with modular `RIG_DRAWERS` architecture.
- Vector rigs, contact rules: `graze` lowers the head (`s.head_down`, quadruped head/horns/ears drawn rotated about `neckPivot` + `neckReach`/`neckDrop`; `localAnchor` rotates `mouth`/`face`/`horn` with it) and only slides the animal horizontally, so the mouth meets the grass top while feet stay on the ground (test `test_graze_lowers_head_to_the_grass_without_sinking_the_body`). Off-centre fruit bodies attach limbs with `hipX`/`armX` in the `drawFruit` spec (grape, banana, mango) — never leave a gap between limb and body. Birds with `canFly` (sparrow) perch with legs and flap only while `fly` is active (`s.flying`). Flower faces scale with bloom (`.26 → .52`) so buds are not covered.
- Vector rig registry: every asset is dispatched through `RIG_DRAWERS` in `remake_vector_engine.js`. Fruits, farm plants/flowers, tools and props register their group function (`drawFruit`/`drawPlant`/`drawTool`/`drawProp`), which keeps the shared parts (limbs, squash, slice, roots, nutrients, hatch). The per-asset drawing lives in `FRUIT_BODIES` (body), `FRUIT_SEEDS` (flesh detail when sliced), `FARM_PLANTS`, `TOOL_DRAWERS` (unknown tools draw as `sprayer`) and `PROP_DRAWERS`. Add a new rig as an entry there, not as another `if (s.asset === …)` branch.
- Vector engine packs (plan `docs/PLAN_remake_vector_farm_health.md`): new rigs/backgrounds go in `bkt_web/static/remake_vector_packs/<pack>.js`, listed in catalog `engine_packs`, and call `RemakeVector.register({ rigs, backgrounds, effects, actionHooks })` with drawing helpers from `RemakeVector.kit`. `register` throws on an id that already exists (packs only add). Every loader uses `remake_vector.engine_sources()` (composer, `renderer_adapters/native_vector.py`, regression test; the library page loads `engine_packs` itself), and it raises `FileNotFoundError` for a missing pack. Never fall back to the core engine: the video would silently miss rigs. Each pack asset declares `pack` in the catalog (`--contact-sheet <pack>` selects by it). Backgrounds are `BACKGROUNDS[preset] = { label, theme, ground_y, draw }`, mirrored in catalog `background_specs`. `catalog.backgrounds` stays a list of ids. `ground_warnings(story)` (returned as `warnings` by `/api/remake/library/validate`) flags people/animals floating above `ground_y`. Weather is `clear|rain|snow|wind|fog|storm|hot`. `wind`/`storm` set `s.wind` unless a keyframe sets `wind`; plants shear with it in both drawing and `worldAnchor` (`windShear`). Pixel regression: `python3 -m unittest tests.test_remake_vector_regression` (every catalog rig, every background × day/night/every weather, every example story; baseline `tests/data/vector_hashes.json`; Chromium runs with software raster `--disable-gpu`, because GPU raster changed hashes under load). A missing baseline fails. Refresh it only on purpose with `python3 tests/test_remake_vector_regression.py --update-hashes`. Contact sheets: `python3 -m bkt_web.remake_vector --contact-sheet <group|pack|ids> --out <file>`. Write them outside `bkt_web/static`.
- Fruit trees and trellis vines (packs `farm_trees`, `trellis`): each rig's `spec` (fruit, slots, fruitScale, flower…) lives in the pack and is mirrored in the catalog, together with anchors `fruit_1`…`fruit_8` (slots past the species count repeat the last one). `PackContractTest` fails if they differ. A tree draws its fruit with the core `FRUIT_BODIES`, centred on `fruit_N`, at size `fruitScale × (0.5 + 0.5·clamp((growth−0.45)/0.55))`. Tree drawings scale with growth like the core `plantPoint`. Vines keep a fixed trellis, so they set catalog `fixed_anchors: true` (anchors do not scale with growth). Pose `fruits` shows the first N slots. `pick` always takes the last visible fruit: at the action's `contact` time (default `start + 0.6`; `showreel` scales it together with start and end) the tree's `fruits` drops by 1, a new fruit actor (no face) appears there, and the `grip` starts, all at once. People reach with IK (`actor_anchor` hand_l/hand_r, the same hand as the grip) and do not move their body; loose `hand` rigs move. `shake` drops exactly one fruit of the tree's species per `fruits` step, and it must touch the background's `ground_y`. Build these events with `remake_vector.tree_pick_events` / `tree_shake_events` (positions from `tree_fruit_placement`); never hand-place the fruit. All fruit trees, temperate ones included (persimmon/peach/pear/cherry_tree), use the single `drawFruitTree` template in `farm_trees.js`; never write a second tree template. `temperate_fruits` only adds the 9 fruits and the `highland_farm`/`snowy_orchard` backgrounds. The engine copies the scene's `background.season` into `s.season` (default summer): spring shows blossoms, autumn turns the canopy orange, winter strips leaves and fruit (except `winterFruit`, e.g. persimmon). Pack fruits/vegetables (group `fruit`/`vegetable`, both drawn by `drawFruit`) compute their own body colour, so each `FRUIT_LIMBS` spec must set `limbColor`; otherwise limbs fall back to the core red (test `test_pack_fruits_and_vegetables_declare_their_limb_colour`). Small bodies set catalog `face_scale`. Root crops (`vegetables` pack) share one `drawRootCrop` template. Parts above ground scale like `plantPoint`; tubers below ground (y > 0) are drawn only when `roots`/`cutaway`/`lift` is > 0. Sea monsters live in pack `sea_monsters` and the wildlife packs draw their own eyes (`face: false`, so they cannot talk). `squirrel` replaced `scrat_squirrel` (too close to the Ice Age character).

- Antigravity quota: both bridge timers (`deploy/tokmatrix-bridge-run.sh` → `/usr/local/bin/tokmatrix-bridge-run` for images, `deploy/tokmatrix-script-bridge-run.sh` for scripts) record each conversation with `deploy/tokmatrix-agent-quota.py` (installed as `/usr/local/bin/tokmatrix-agent-quota`, state in `/var/lib/tokmatrix-bridge/`) and skip dispatch until the `quotaResetTimeStamp` in a quota-exceeded (HTTP 429) error body found there. Only that absolute timestamp is trusted: the agent quotes old "reset after …" text, and every conversation embeds this file, so the bare error-reason word proves nothing. An image-model limit blocks only the image bridge; a full text-model name (`gemini-*-flash|pro`) blocks both. A 403 whose ErrorInfo reason is account verification (Google "Verify your account to continue") is reported as model `VALIDATION_REQUIRED` for every bridge of that account, and `tokmatrix-rotator rotate` then disables the account (manual Google verification needed) instead of waiting for a quota reset. The script bridge only waits while its own last conversation (`script.cids`) is still being written, not while image conversations run; rotations restart `antigravity.service` and kill in-flight conversations.

- Autopilot Engine: package `bkt_web/autopilot/` (store, channels, planner, safety, scheduler, publisher, cleanup, cycle, engine) auto-creates videos daily for the TikTok accounts via Matrix batches and schedules publishing. Each TikTok account is mapped 1:1 to a Matrix channel config (fixed niche). `safety.check_niche_match` blocks publishing unless plan, account mapping, the job's Matrix channel and the job's topic all have the same niche. Publishing is idempotent: an existing upload task for (slug, account) only moves the job to SCHEDULED, never creates a second task. The engine (`engine.AutopilotEngine`) has states stopped/disabled/paused/idle/running/stopping; one cycle or manual action at a time (others get `Busy` → HTTP 409); stop/pause halt long steps, including batch-matrix/rsync subprocesses, at safe points; interrupted batches resume with `--resume`. Every run is recorded in `autopilot_runs`, and logs in `autopilot_events`. Publishing can be held while videos are still produced: `publish_hold_until` (epoch, `deploy/scheduler_ops.py hold --hours N` / `release`), and each account must "warm up" `warmup_hours` (default 24) after its cookie changes — `channels.cookie_injected_at` is stamped by SQLite triggers whenever `cookie_hash` changes (re-importing the same cookie does not reset it; pre-existing accounts are 0 = warmed). Held jobs stay `READY_TO_PUBLISH`. `min_lead_hours` makes a video wait that long after it became `READY_TO_PUBLISH` before its slot (24 keeps a one-day buffer of finished videos). Renders are capped machine-wide by `compare_studio/matrix/render/render-slots.mjs` (`MATRIX_RENDER_SLOTS`, default half the CPUs; lock files with PID under `compare_studio/.runtime/render-slots`, stale ones reclaimed). Matrix scripts are longer than the templates' sample content, so `applyMatrixLayoutFixes` (native-engine-adapter) injects a deterministic fit script (shrinks `#story-content` and `#live-punchline` to their boxes, refits on punchline changes), marks newspaper's decorative tape/stamp text `data-layout-allow-occlusion`, and kinetic punchlines are short phrases (`shortPunchline`); a failed render **and a failed Video QA** retry from ASSET_QA so the project is rebuilt with the current engine code (re-rendering the same index.html repeated the same defect, e.g. vox's black tail, until retries ran out). The "existing render has a different source composition" guard only protects renders that passed Video QA (`meta.matrix.rendered_composition_hash`); a QA-rejected MP4 is moved to `renders/<slug>.rejected.mp4` and rebuilt. Running batch-matrix processes keep the engine code they loaded at start, so after deploying an engine fix stop them (they resume next cycle). Matrix video QA allows 25–90 s (`MATRIX_VIDEO_QA`; German scripts run 67–74 s, TikTok Creator Rewards needs > 60 s). Reviving a job that rewrites its script or changes engine (or failed on a snapshot/composition check) first moves its old `videos/<slug>` to `compare_studio/.runtime/retired-videos/`. A batch-matrix that exceeds `batch_timeout_minutes` leaves its plan `producing` for resume. `hyperframes check` prints its findings on stdout, so the stored error only shows stderr — rerun `npm run check` in the video dir to see why. Failed videos are revived by `bkt_web/autopilot/revive.py` each cycle (`matrix_db.revive_job`, up to `max_revives`=2, only if the channel is still mapped to a TikTok account, 10-minute cool-down): script errors → PLANNING (script rewritten), render errors → ASSET_QA, others/engine change → SCRIPT_QA; the job keeps its channel, so it still posts to the same account. `deploy/setup_vps_optimization.sh` sizes MemoryHigh/Max, swap and render slots from the real CPU/RAM and protects `antigravity.service` with MemoryLow. Channels only get engines the native renderer can build (`RENDERABLE_ENGINES` in `native-engine-adapter.mjs`: mystery, newspaper, vox, folklore, kinetic, science, plus the extended engines tierlist, survival, chalk, wildlife, compare; `pickEngine` in `template-selector.mjs`); a channel with no renderable engine falls back to `kinetic` (`FALLBACK_ENGINE`). Batches run in background threads (`planner.launch_pending_plans`, max `max_concurrent_batches`) so each cycle (`check_interval_seconds`, default 600) can publish finished videos; producing plans with unfinished jobs are resumed every cycle; a batch-matrix killed by a signal counts as halted, not failed. Upload captions come from publish_kit text, but hashtags come from `autopilot/captions.py` (niche + account language), never publish_kit's hard-coded tags. Each account posts at a fixed per-account minute offset (`slot_jitter_minutes`, default 45) and prefers its own "home hour" among `posting_hours` (`spread_posting_hours`), so accounts do not all hit the earliest slot of the single-worker uploader. Batches only include Matrix channels that are mapped to a TikTok account (`--channel-ids`, angles generated in rounds of ≤10); `batch_timeout_minutes` (default 240) and `matrix_workers` (default 3) are config keys. Topics come only from `compare_studio/config/topics/<niche>.txt` (30 English topics per niche) and Matrix `topics` rows with status READY (`topic_source` curated|file|matrix); with no topic left, a niche is skipped. Cleanup only handles `upload_tasks.status='SUCCESS'`, requires `archive_vps_host` (with the remote size verified) unless `cleanup_without_backup=true`, and deletes exactly `compare_studio/projects/<job_id>`. New batches are skipped while free disk is below `min_free_disk_gb`. `bkt_web/autopilot_routes.py` exposes `/api/autopilot/*` (start/stop/pause/resume/run-now/runs/config/map/plans/plans/{id}/retry/topics/publish-ready/cleanup/logs); config values are validated. DB: `storage/autopilot.db`. Config default is `enabled: false`. Tests: `python3 -m unittest tests.test_autopilot_engine tests.test_autopilot_language`. Syntax check: `python3 -c "import bkt_web.autopilot; import bkt_web.autopilot_routes"`.
- Disk housekeeping: `bkt_web/autopilot/housekeeping.py` runs in every Autopilot cleanup step (at most every `housekeeping_interval_minutes`=60; manual cleanup forces it; each item 0 = off, independent of `cleanup_enabled`): deletes `storage/antigravity_bridge/archive` files older than `bridge_archive_keep_hours` (12; they are copies moved there after import), `static/generated_images` files older than `generated_images_keep_days` (1) only when an identical file (size + md5) exists under `compare_studio/videos/*/assets`, media of videos posted SUCCESS more than `purge_posted_after_days` (3) ago with no other task needing them (keeps `meta.json`/`index.html`/`images.json`, computes the fingerprint first, sets `archived_at`), and `~/.npm/_npx` HyperFrames dirs except the `npx_keep_versions` (2) newest, versions pinned in `compare_studio/{matrix/render,tools}/*.mjs` (0.7.58) and anything a running process uses.
